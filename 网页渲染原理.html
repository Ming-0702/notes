    Web 渲染原理

    Web 渲染原理研究的是：浏览器拿到 HTML、CSS、JavaScript、图片等资源后，如何把它们转换成用户最终看到的页面。

    简化流程：

    HTML/CSS/JS 下载
  -> HTML 解析生成 DOM 树
  -> CSS 解析生成 CSSOM 树
  -> DOM + CSSOM 合成 Render Tree
  -> Layout 计算布局
  -> Paint 绘制像素
  -> Composite 合成图层
  -> 显示到屏幕

    1. 浏览器主要组成

    浏览器不是单个模块，而是多个模块协同工作。

    组成部分 作用
    用户界面 地址栏、前进后退、书签栏等
    浏览器引擎 协调 UI 和渲染引擎
    渲染引擎 解析 HTML/CSS，布局、绘制页面
    JavaScript 引擎 解析和执行 JavaScript
    网络模块 发送 HTTP/HTTPS 请求，下载资源
    存储模块 管理 Cookie、LocalStorage、Cache 等
    GPU 进程 处理图层合成、部分图形加速

    常见渲染引擎：

    • Blink：Chrome、Edge 使用。
    • WebKit：Safari 使用。
    • Gecko：Firefox 使用。

    常见 JavaScript 引擎：

    • V8：Chrome、Edge、Node.js 使用。
    • JavaScriptCore：Safari 使用。
    • SpiderMonkey：Firefox 使用。

    2. 多进程架构

    现代浏览器通常采用多进程架构，提高稳定性和安全性。

    常见进程：

    进程 作用
    浏览器主进程 管理窗口、地址栏、书签、下载等
    渲染进程 负责页面解析、JS 执行、布局、绘制
    网络进程 负责网络请求
    GPU 进程 负责图形加速和图层合成
    插件进程 运行浏览器插件

    多进程的好处：

    • 一个页面崩溃不一定影响整个浏览器。
    • 不同站点可以隔离，安全性更高。
    • 可以更好地利用多核 CPU。

    3. 关键渲染路径

    关键渲染路径是浏览器从接收 HTML 到首次渲染页面所经历的关键步骤。

    核心步骤：

    1. 解析 HTML，构建 DOM 树。
    2. 解析 CSS，构建 CSSOM 树。
    3. DOM 和 CSSOM 合成渲染树。
    4. 计算每个节点的位置和大小。
    5. 把节点绘制到不同图层。
    6. 合成图层并显示到屏幕。

    优化关键渲染路径的目标是让页面更快出现可见内容。

    4. HTML 解析与 DOM 树

    浏览器下载 HTML 后，会边下载边解析。

    HTML 解析过程：

    字节流 -> 字符 -> Token -> Node -> DOM Tree

    DOM 是 Document Object Model，表示页面结构。

    示例 HTML：

    <!doctype html>
<html>
  <head>
    <title>Demo</title>
  </head>
  <body>
    <h1>Hello</h1>
    <p>Web rendering</p>
  </body>
</html>

    对应 DOM 树大致是：

    Document
  html
    head
      title
    body
      h1
      p

    DOM 树只描述文档结构，不包含最终样式和布局位置。

    5. CSS 解析与 CSSOM 树

    CSSOM 是 CSS Object Model，表示 CSS 规则解析后的结构。

    CSS 解析过程：

    CSS 文本 -> Token -> Rule -> CSSOM Tree

    示例 CSS：

    body {
  font-size: 16px;
}

h1 {
  color: red;
}

    CSSOM 会记录选择器、属性、继承关系和层叠结果。

    CSSOM 的特点：

    • CSS 会阻塞渲染，因为浏览器必须知道样式才能正确绘制页面。
    • CSS 不一定阻塞 DOM 解析，但会影响渲染树生成。
    • 外部 CSS 文件下载慢，会延迟首次渲染。

    6. JavaScript 对解析的影响

    普通 <script> 会阻塞 HTML 解析。

    原因：

    • JavaScript 可能通过 document.write() 修改 HTML。
    • JavaScript 可能读取或修改 DOM。
    • JavaScript 可能读取样式计算结果。

    示例：

    <script src="main.js"></script>

    浏览器遇到普通脚本时通常会：

    1. 暂停 HTML 解析。
    2. 下载脚本。
    3. 执行脚本。
    4. 继续解析 HTML。

    defer 和 async 可以减少阻塞。

    写法 下载行为 执行时机 是否保证顺序
    普通 script 阻塞解析时下载 下载后立即执行 是
    defer 不阻塞 HTML 解析 DOM 解析完成后执行 是
    async 不阻塞 HTML 解析 下载完成后立即执行 否

    使用建议：

    • 依赖 DOM 的脚本可以使用 defer。
    • 独立统计、广告脚本可以使用 async。
    • 关键交互脚本应控制体积，避免长时间占用主线程。

    7. 渲染树 Render Tree

    浏览器会把 DOM 和 CSSOM 合成渲染树。

    渲染树只包含需要显示的节点。

    不会进入渲染树的节点：

    • display: none 的元素。
    • head、script、meta 等不直接显示的节点。

    会进入渲染树但可能不可见的节点：

    • visibility: hidden 的元素仍占据布局空间。
    • opacity: 0 的元素仍参与布局和绘制。

    对比：

    样式 是否占据空间 是否渲染
    display: none 否 否
    visibility: hidden 是 不可见
    opacity: 0 是 透明

    8. 布局 Layout

    布局也叫回流 Reflow。它负责计算每个可见元素的几何信息。

    布局阶段会计算：

    • 元素宽高。
    • 元素位置。
    • 行盒、块盒、弹性盒、网格布局等。
    • 父子元素之间的约束关系。

    可能触发布局的操作：

    • 修改元素尺寸：width、height。
    • 修改元素位置：top、left、margin。
    • 添加或删除 DOM 节点。
    • 修改字体大小。
    • 改变窗口大小。
    • 读取某些布局属性后又修改样式。

    常见会强制浏览器计算布局的属性：

    offsetWidth
offsetHeight
offsetTop
offsetLeft
clientWidth
clientHeight
scrollTop
scrollHeight
getBoundingClientRect()
getComputedStyle()

    如果在循环中反复读写这些属性，容易造成布局抖动。

    9. 绘制 Paint

    绘制阶段会把渲染树中的节点转换为绘制指令。

    绘制内容包括：

    • 文本。
    • 颜色。
    • 边框。
    • 阴影。
    • 图片。
    • 背景。

    常见会触发重绘的操作：

    • 修改 color。
    • 修改 background-color。
    • 修改 box-shadow。
    • 修改 visibility。

    重绘不一定重新布局，但仍然有性能成本。

    10. 合成 Composite

    浏览器可能会把页面拆分为多个图层。绘制完成后，合成线程把这些图层按正确顺序合成到屏幕上。

    可能创建独立合成层的情况：

    • 使用 transform。
    • 使用 opacity 动画。
    • 使用 position: fixed。
    • 使用 will-change。
    • 使用视频、Canvas、WebGL。

    合成的优势：

    • 某些动画可以只在合成层完成，不触发布局和绘制。
    • transform 和 opacity 通常比修改 left、top 更流畅。

    示例：

    /* 推荐用于动画 */
.box {
  transform: translateX(100px);
}

/* 容易触发布局 */
.box {
  left: 100px;
}

    注意：不要滥用 will-change，过多图层会增加内存占用和合成成本。

    11. 回流、重绘、合成的区别

    类型 英文 影响范围 性能成本
    回流 Layout / Reflow 重新计算布局 最大
    重绘 Paint / Repaint 重新绘制像素 中等
    合成 Composite 合成已有图层 较小

    性能成本大致：

    回流 > 重绘 > 合成

    例子：

    操作 可能触发
    改 width 回流 + 重绘 + 合成
    改 color 重绘 + 合成
    改 transform 合成
    改 opacity 合成
    添加 DOM 节点 回流 + 重绘 + 合成

    12. 浏览器主线程与事件循环

    渲染进程中有一个重要的主线程，负责大量页面工作。

    主线程通常负责：

    • 执行 JavaScript。
    • 解析 HTML。
    • 样式计算。
    • 布局。
    • 绘制准备。
    • 处理用户输入事件。

    如果 JavaScript 长时间占用主线程，页面就可能卡顿，用户点击、滚动也会变慢。

    事件循环大致流程：

    执行一个宏任务
  -> 清空微任务队列
  -> 必要时执行渲染
  -> 执行下一个宏任务

    常见宏任务：

    • setTimeout
    • setInterval
    • 用户交互事件
    • 网络回调
    • 整体脚本执行

    常见微任务：

    • Promise.then
    • queueMicrotask
    • MutationObserver

    示例：

    console.log('start');

setTimeout(() => {
  console.log('timeout');
});

Promise.resolve().then(() => {
  console.log('promise');
});

console.log('end');

    输出顺序：

    start
end
promise
timeout

    13. 一帧是如何渲染的

    大多数屏幕刷新率是 60Hz，也就是每秒刷新 60 次。

    每帧时间约为：

    1000ms / 60 ≈ 16.7ms

    一帧中可能包含：

    1. 处理输入事件。
    2. 执行 JavaScript。
    3. 执行 requestAnimationFrame 回调。
    4. 样式计算。
    5. 布局。
    6. 绘制。
    7. 合成。
    8. 显示到屏幕。

    如果一帧内工作超过 16.7ms，就可能掉帧，用户会感觉卡顿。

    requestAnimationFrame 适合做动画，因为它会在浏览器下一次绘制前执行。

    function move() {
  element.style.transform = 'translateX(100px)';
  requestAnimationFrame(move);
}

requestAnimationFrame(move);

    14. 资源加载对渲染的影响

    不同资源对渲染的影响不同。

    资源 对渲染的影响
    HTML 渲染入口，必须先解析
    CSS 阻塞渲染，影响 CSSOM 和渲染树
    普通 JS 阻塞 HTML 解析
    defer JS 不阻塞 HTML 解析，DOM 完成后执行
    async JS 不阻塞 HTML 解析，下载完立即执行
    图片 通常不阻塞 DOM 解析，但会影响布局和 LCP
    字体 可能导致文字不可见或字体切换

    常见资源优化手段：

    <link rel="preload" href="/style.css" as="style">
<link rel="preconnect" href="https://cdn.example.com">
<script src="/main.js" defer></script>
<img src="/hero.jpg" loading="lazy" alt="">

    说明：

    • preload：提前加载当前页面马上要用的关键资源。
    • preconnect：提前建立到第三方源的连接。
    • defer：延后执行脚本，减少解析阻塞。
    • loading="lazy"：图片懒加载，减少首屏资源压力。

    15. 前端性能指标

    常见页面性能指标：

    指标 含义
    FP First Paint，首次绘制
    FCP First Contentful Paint，首次内容绘制
    LCP Largest Contentful Paint，最大内容绘制
    CLS Cumulative Layout Shift，累计布局偏移
    TTFB Time To First Byte，首字节时间
    TTI Time To Interactive，可交互时间
    INP Interaction to Next Paint，交互到下一次绘制的延迟

    重点理解：

    • FCP 关注页面何时开始出现内容。
    • LCP 关注首屏主要内容何时完成显示。
    • CLS 关注页面是否发生意外布局跳动。
    • INP 关注用户交互后页面响应是否及时。
    • TTFB 反映网络和服务端响应速度。

    16. 常见优化思路

    减少网络耗时：

    • 开启 HTTP 缓存。
    • 使用 CDN。
    • 压缩 HTML、CSS、JavaScript。
    • 使用 HTTP/2 或 HTTP/3。
    • 减少不必要请求。

    减少渲染阻塞：

    • 关键 CSS 内联或优先加载。
    • 非关键 CSS 延迟加载。
    • JavaScript 使用 defer 或按需加载。
    • 减少首屏依赖的大体积资源。

    减少回流和重绘：

    • 批量修改 DOM。
    • 避免循环中交替读取布局属性和修改样式。
    • 动画优先使用 transform 和 opacity。
    • 避免频繁修改影响布局的 CSS 属性。

    优化图片和字体：

    • 使用合适尺寸的图片。
    • 使用 WebP、AVIF 等高压缩格式。
    • 给图片设置 width 和 height，减少布局偏移。
    • 字体按需加载，避免加载过多字重。

    优化 JavaScript：

    • 拆分长任务。
    • 减少主线程阻塞。
    • 使用 Web Worker 处理复杂计算。
    • 对滚动、输入等高频事件使用节流或防抖。
