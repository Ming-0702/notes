# 域名和域名解析学习笔记

## 一、域名是什么

域名是互联网上用于标识网站或服务的可读名称。

例如：

```text
www.example.com
```

人更容易记住域名，计算机真正通信时需要 IP 地址。域名解析的作用就是把域名转换成对应的 IP 地址或其他服务信息。

```text
www.example.com -> 93.184.216.34
```

## 二、域名层级结构

域名是分层的，从右往左层级越来越低。

以 `www.example.com` 为例：

```text
www.example.com.
│   │       │   │
│   │       │   └─ 根域 root，通常省略不写
│   │       └──── 顶级域 TLD
│   └──────────── 二级域
└──────────────── 子域名 / 主机名
```

### 1. 根域

根域是 DNS 层级的最顶层，完整域名最后其实有一个点：

```text
www.example.com.
```

日常使用时最后的点通常省略。

### 2. 顶级域 TLD

常见顶级域：

- `.com`
- `.net`
- `.org`
- `.cn`
- `.edu`
- `.io`
- `.dev`

顶级域由对应的注册局管理。

### 3. 二级域

例如 `example.com` 中的 `example` 就是二级域。

一般购买域名时，买到的是类似下面这样的域名：

```text
example.com
example.cn
my-site.net
```

### 4. 子域名

子域名是在主域名前继续增加的层级。

例如：

```text
www.example.com
api.example.com
blog.example.com
dev.api.example.com
```

常见用途：

- `www`：网站主页。
- `api`：后端接口。
- `admin`：管理后台。
- `cdn`：静态资源。
- `mail`：邮件服务。

### 5. FQDN

FQDN 是 Fully Qualified Domain Name，完全限定域名。

严格来说完整写法是：

```text
www.example.com.
```

最后的点表示根域。

## 三、域名注册相关概念

### 1. 注册局 Registry

注册局负责管理某个顶级域。

例如 `.com`、`.cn` 这样的顶级域背后都有对应的注册局。

### 2. 注册商 Registrar

注册商是提供域名购买和管理服务的平台。

用户通常通过注册商购买域名、续费域名、设置 DNS 服务器。

常见功能：

- 查询域名是否可注册。
- 注册域名。
- 续费域名。
- 修改域名联系人信息。
- 设置 nameserver。
- 开启域名锁。

### 3. 注册人 Registrant

注册人是域名的持有人。

域名到期后如果没有续费，可能进入宽限期、赎回期，最后被释放重新注册。

### 4. WHOIS

WHOIS 用来查询域名注册信息。

可能包含：

- 注册商。
- 注册时间。
- 到期时间。
- 域名状态。
- DNS 服务器。
- 联系人信息。

很多域名会开启隐私保护，因此不一定能看到真实联系人信息。

### 5. 域名状态

常见状态：

| 状态 | 含义 |
| --- | --- |
| `clientTransferProhibited` | 禁止转移，通常是域名锁 |
| `ok` | 正常状态 |
| `pendingDelete` | 等待删除 |
| `redemptionPeriod` | 赎回期 |
| `serverHold` | 注册局暂停解析 |

如果域名状态异常，即使 DNS 记录配置正确，也可能无法正常解析。

## 四、DNS 是什么

DNS 是 Domain Name System，域名系统。

DNS 的作用：

- 把域名解析为 IP 地址。
- 指定邮件服务器。
- 做域名所有权验证。
- 提供服务发现。
- 支持 CDN、负载均衡和容灾。

DNS 是分布式系统，不是某一台服务器保存所有域名记录。

## 五、DNS 中的重要角色

### 1. Resolver 解析器

解析器负责帮用户查询域名结果。

常见解析器：

- 运营商 DNS。
- 公共 DNS。
- 公司内网 DNS。
- 本机 DNS 缓存。

用户电脑通常不会直接询问根 DNS，而是把请求交给递归解析器。

### 2. Recursive Resolver 递归解析器

递归解析器负责代替客户端完成完整查询。

如果缓存中没有结果，它会继续询问：

```text
根 DNS -> 顶级域 DNS -> 权威 DNS
```

最后把结果返回给客户端，并缓存一段时间。

### 3. Root DNS 根 DNS

根 DNS 知道各个顶级域 DNS 在哪里。

它不会直接知道 `www.example.com` 的 IP，但它知道 `.com` 应该去问谁。

### 4. TLD DNS 顶级域 DNS

顶级域 DNS 负责某个顶级域。

例如 `.com` 的 TLD DNS 知道 `example.com` 的权威 DNS 服务器是谁。

### 5. Authoritative DNS 权威 DNS

权威 DNS 保存某个域名真正的 DNS 记录。

例如 `example.com` 的权威 DNS 会保存：

- `www.example.com` 对应哪个 IP。
- `api.example.com` 对应哪个 IP。
- `example.com` 使用哪些邮件服务器。
- `example.com` 的 TXT 验证记录。

## 六、域名解析过程

以访问 `www.example.com` 为例：

```text
浏览器访问 www.example.com
  -> 检查浏览器 DNS 缓存
  -> 检查操作系统 DNS 缓存
  -> 查询本地配置的递归 DNS
  -> 递归 DNS 查询根 DNS
  -> 根 DNS 返回 .com 的 TLD DNS
  -> 递归 DNS 查询 .com TLD DNS
  -> TLD DNS 返回 example.com 的权威 DNS
  -> 递归 DNS 查询权威 DNS
  -> 权威 DNS 返回 www.example.com 的记录
  -> 递归 DNS 把结果返回给客户端
  -> 浏览器拿到 IP 后发起连接
```

简化理解：

```text
客户端问递归 DNS：www.example.com 是多少？
递归 DNS 负责一路问到权威 DNS，然后把答案返回。
```

## 七、递归查询和迭代查询

### 1. 递归查询

客户端要求 DNS 服务器给出最终结果。

如果 DNS 服务器不知道，它需要继续帮客户端查。

常见场景：

```text
电脑 -> 运营商 DNS / 公共 DNS
```

### 2. 迭代查询

DNS 服务器不知道最终结果时，只告诉你下一步应该问谁。

常见场景：

```text
递归 DNS -> 根 DNS
递归 DNS -> TLD DNS
递归 DNS -> 权威 DNS
```

## 八、DNS 记录类型

### 1. 常见记录

| 类型 | 作用 | 示例 |
| --- | --- | --- |
| A | 域名指向 IPv4 地址 | `www -> 192.0.2.10` |
| AAAA | 域名指向 IPv6 地址 | `www -> 2001:db8::1` |
| CNAME | 域名别名，指向另一个域名 | `www -> example.com` |
| MX | 指定邮件服务器 | `example.com -> mail.example.com` |
| TXT | 文本记录，常用于验证和反垃圾邮件 | SPF、DKIM、DMARC |
| NS | 指定权威 DNS 服务器 | `ns1.example-dns.com` |
| SOA | 区域起始授权记录 | 包含序列号、刷新时间等 |
| SRV | 指定某服务的主机和端口 | SIP、LDAP 等 |
| CAA | 指定允许哪些 CA 签发证书 | `letsencrypt.org` |
| PTR | 反向解析，IP 指向域名 | 邮件服务器常用 |

### 2. A 记录

A 记录把域名解析到 IPv4 地址。

示例：

```text
www.example.com -> 203.0.113.10
```

适合：

- 网站服务器。
- API 服务器。
- 直接绑定公网 IP 的服务。

### 3. AAAA 记录

AAAA 记录把域名解析到 IPv6 地址。

示例：

```text
www.example.com -> 2001:db8::10
```

如果网站支持 IPv6，可以同时配置 A 和 AAAA。

### 4. CNAME 记录

CNAME 是别名记录，把一个域名指向另一个域名。

示例：

```text
www.example.com -> example.github.io
```

注意：

- CNAME 的目标应该是域名，不是 IP。
- 一个主机名如果配置了 CNAME，通常不能再同时配置 A、MX、TXT 等其他记录。
- 根域名 `example.com` 是否支持 CNAME 取决于 DNS 服务商，有些平台提供 ALIAS、ANAME 或 CNAME Flattening 来解决根域名指向另一个域名的问题。

### 5. MX 记录

MX 记录指定收邮件的服务器。

示例：

```text
example.com MX 10 mail.example.com
```

数字表示优先级，数字越小优先级越高。

邮件服务通常还需要 TXT 记录配合：

- SPF
- DKIM
- DMARC

### 6. TXT 记录

TXT 记录保存文本信息。

常见用途：

- 证明域名所有权。
- 配置 SPF。
- 配置 DKIM。
- 配置 DMARC。
- 第三方平台验证。

示例：

```text
example.com TXT "v=spf1 include:_spf.example.net -all"
```

### 7. NS 记录

NS 记录指定某个域名由哪些权威 DNS 服务器负责。

在注册商处设置的 nameserver 决定整个域名使用哪组权威 DNS。

例如：

```text
ns1.example-dns.com
ns2.example-dns.com
```

### 8. SOA 记录

SOA 是 Start of Authority，表示 DNS 区域的起始授权信息。

包含：

- 主 DNS 服务器。
- 管理员邮箱。
- 序列号。
- 刷新时间。
- 重试时间。
- 过期时间。
- 最小 TTL。

普通网站配置中很少直接修改 SOA，但排查权威 DNS 问题时会看到它。

### 9. CAA 记录

CAA 用来限制哪些证书颁发机构可以给域名签发证书。

示例：

```text
example.com CAA 0 issue "letsencrypt.org"
```

如果配置错误，可能导致 HTTPS 证书申请失败。

### 10. PTR 记录

PTR 用于反向解析，把 IP 地址解析回域名。

常见于邮件服务器，因为很多邮件服务会检查发送方 IP 是否有合理的反向解析。

PTR 记录通常由 IP 所属的云厂商、机房或运营商配置，不是在普通域名 DNS 面板中配置。

## 九、主机记录、记录值和线路

### 1. 主机记录

主机记录表示要配置哪个子域。

常见写法：

| 主机记录 | 完整域名 |
| --- | --- |
| `@` | `example.com` |
| `www` | `www.example.com` |
| `api` | `api.example.com` |
| `*` | 泛解析，例如 `anything.example.com` |

### 2. 记录值

记录值是解析目标。

例如：

- A 记录的记录值是 IPv4 地址。
- AAAA 记录的记录值是 IPv6 地址。
- CNAME 记录的记录值是另一个域名。
- MX 记录的记录值是邮件服务器域名。

### 3. 解析线路

有些 DNS 服务商支持按线路返回不同结果。

例如：

- 默认线路。
- 电信线路。
- 联通线路。
- 移动线路。
- 海外线路。

这可以用于访问优化，但也会让不同地区查询到不同 IP，排查时要注意查询来源。

## 十、TTL 和 DNS 缓存

TTL 是 Time To Live，表示 DNS 记录可以被缓存多久。

例如 TTL 为 600：

```text
递归 DNS 可以把这个结果缓存 600 秒
```

### 1. TTL 的影响

TTL 越大：

- 缓存时间长。
- DNS 查询压力小。
- 修改解析后生效更慢。

TTL 越小：

- 修改解析后更快生效。
- DNS 查询压力更大。
- 适合迁移、切换前临时降低。

### 2. 修改解析为什么不是立刻生效

原因：

- 递归 DNS 缓存还没过期。
- 本机 DNS 缓存还没刷新。
- 浏览器有自己的 DNS 缓存。
- 不同地区递归 DNS 更新时间不同。
- 权威 DNS 服务器之间同步需要时间。

通常说的“DNS 生效时间”本质上主要受缓存和 TTL 影响。

### 3. 切换服务器前的做法

如果计划把域名从旧服务器切到新服务器：

1. 提前把 TTL 调低，例如 300 秒。
2. 等旧 TTL 过期。
3. 修改 A 记录到新 IP。
4. 验证不同地区解析结果。
5. 确认稳定后再把 TTL 调回正常值。

## 十一、常见域名配置场景

### 1. 域名指向网站服务器

假设服务器公网 IP 是：

```text
203.0.113.10
```

配置：

| 主机记录 | 类型 | 记录值 |
| --- | --- | --- |
| `@` | A | `203.0.113.10` |
| `www` | A | `203.0.113.10` |

访问：

```text
https://example.com
https://www.example.com
```

还需要：

- Web 服务器监听 80/443。
- 防火墙或安全组放行 80/443。
- 配置 HTTPS 证书。
- Web 服务中绑定对应域名。

### 2. `www` 指向根域名

配置：

| 主机记录 | 类型 | 记录值 |
| --- | --- | --- |
| `@` | A | `203.0.113.10` |
| `www` | CNAME | `example.com` |

这样 `www.example.com` 会作为别名解析到 `example.com`。

### 3. 子域名指向不同服务

| 主机记录 | 类型 | 记录值 | 用途 |
| --- | --- | --- | --- |
| `www` | A | `203.0.113.10` | 官网 |
| `api` | A | `203.0.113.20` | API |
| `admin` | A | `203.0.113.30` | 后台 |
| `cdn` | CNAME | `cdn-provider.example.net` | 静态资源 |

### 4. 使用 CDN

CDN 通常会要求配置 CNAME。

示例：

```text
www.example.com CNAME www.example.com.cdn-provider.net
```

流程：

```text
用户访问 www.example.com
  -> DNS 返回 CDN 域名
  -> CDN 根据地区和网络返回就近节点
  -> 用户访问 CDN 节点
  -> CDN 命中缓存或回源到源站
```

注意：

- CDN 平台通常还要配置源站。
- HTTPS 证书需要在 CDN 上配置。
- 源站要限制不必要的公网访问时，需要考虑 CDN 回源 IP。

### 5. 配置邮箱

邮件服务一般需要：

- MX 记录。
- SPF TXT 记录。
- DKIM TXT 记录。
- DMARC TXT 记录。

示例：

```text
example.com MX 10 mail.example.com
mail.example.com A 203.0.113.50
example.com TXT "v=spf1 mx -all"
_dmarc.example.com TXT "v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com"
```

具体值要以邮件服务商提供的配置为准。

### 6. 第三方平台域名验证

很多平台会要求添加 TXT 记录证明域名所有权。

例如：

```text
example.com TXT "verification=abc123"
```

添加后平台会查询 DNS 记录，确认你能控制该域名。

### 7. 域名跳转

DNS 本身不负责 HTTP 跳转。

例如要实现：

```text
example.com -> https://www.example.com
```

需要在以下位置配置重定向：

- Web 服务器。
- CDN。
- 负载均衡。
- 域名服务商提供的 URL 转发功能。

DNS 只能告诉客户端去哪个 IP 或域名，不能直接返回 HTTP 301/302。

## 十二、域名和 HTTPS 证书

HTTPS 证书必须和访问域名匹配。

例如访问：

```text
https://api.example.com
```

证书必须包含：

```text
api.example.com
```

或者使用通配符证书：

```text
*.example.com
```

### 1. 常见证书类型

| 类型 | 示例 | 说明 |
| --- | --- | --- |
| 单域名证书 | `www.example.com` | 只保护一个域名 |
| 多域名证书 | `example.com`、`www.example.com` | 一个证书包含多个域名 |
| 通配符证书 | `*.example.com` | 保护一级子域名 |

注意：

```text
*.example.com
```

可以匹配：

```text
www.example.com
api.example.com
```

不能匹配：

```text
dev.api.example.com
```

### 2. DNS 验证

申请证书时，CA 可能要求添加 TXT 记录完成 DNS 验证。

常见记录：

```text
_acme-challenge.example.com TXT "xxxx"
```

验证通过后才能签发证书。

## 十三、常用排查命令

### 1. Windows

```powershell
nslookup example.com
nslookup www.example.com
nslookup -type=mx example.com
nslookup -type=txt example.com
ipconfig /flushdns
```

说明：

- `nslookup example.com`：查询默认 A 记录。
- `-type=mx`：查询 MX 记录。
- `-type=txt`：查询 TXT 记录。
- `ipconfig /flushdns`：清理 Windows DNS 缓存。

### 2. Linux / macOS

```bash
dig example.com
dig example.com A
dig example.com AAAA
dig example.com MX
dig example.com TXT
dig www.example.com CNAME
dig +trace www.example.com
```

说明：

- `dig`：常用 DNS 查询工具。
- `dig +trace`：从根域开始追踪解析链路。

指定 DNS 服务器查询：

```bash
dig @8.8.8.8 example.com
dig @1.1.1.1 example.com
```

查询权威 DNS：

```bash
dig example.com NS
```

### 3. 查看本机连接

```bash
ping example.com
curl -I https://example.com
traceroute example.com
```

Windows：

```powershell
ping example.com
curl -I https://example.com
tracert example.com
```

注意：`ping` 成功不代表 HTTP 服务正常，`ping` 失败也不一定代表网站不可访问，因为服务器或防火墙可能禁用了 ICMP。

## 十四、常见问题排查

### 1. 域名解析不到

现象：

```text
NXDOMAIN
```

可能原因：

- 域名没有注册。
- 域名过期。
- 主机记录写错。
- 权威 DNS 中没有该记录。
- nameserver 配置错误。

排查：

```bash
dig example.com NS
dig www.example.com
dig +trace www.example.com
```

### 2. 解析到了旧 IP

可能原因：

- 递归 DNS 缓存未过期。
- 本机 DNS 缓存未清理。
- 浏览器缓存。
- 修改了错误的 DNS 服务商面板。
- 权威 DNS 还没同步。

排查：

```bash
dig @权威DNS www.example.com
dig @8.8.8.8 www.example.com
dig @1.1.1.1 www.example.com
```

如果权威 DNS 返回新 IP，而公共 DNS 返回旧 IP，多半是缓存还没过期。

### 3. 能 ping IP，但不能访问域名

可能原因：

- DNS 解析失败。
- 域名解析到错误 IP。
- Web 服务没有绑定该域名。
- HTTPS 证书不匹配。
- CDN 或反向代理配置错误。

排查顺序：

1. 查域名解析结果。
2. 直接访问 IP 测试服务。
3. 检查 Web 服务器虚拟主机配置。
4. 检查 80/443 端口。
5. 检查 HTTPS 证书。

### 4. 域名能解析，但网站打不开

DNS 只负责把域名解析到目标地址。网站打不开不一定是 DNS 问题。

继续检查：

- 服务器是否运行。
- Web 服务是否启动。
- 端口是否开放。
- 云服务器安全组是否放行。
- 防火墙是否阻拦。
- Nginx / Apache / 应用日志是否报错。
- HTTPS 证书是否正确。

### 5. CNAME 配置后不生效

可能原因：

- CNAME 和 A 记录冲突。
- CNAME 目标域名写错。
- CNAME 目标本身无法解析。
- 在根域名配置 CNAME，但服务商不支持。
- 缓存未过期。

### 6. 邮件收不到或进入垃圾箱

检查：

- MX 记录是否正确。
- SPF 是否正确。
- DKIM 是否正确。
- DMARC 是否正确。
- 发送服务器 IP 是否有 PTR 反向解析。
- 邮件服务商是否要求额外验证。

### 7. HTTPS 证书申请失败

可能原因：

- DNS 验证 TXT 记录未生效。
- CAA 记录限制了证书颁发机构。
- 证书申请域名和实际记录不一致。
- 使用了 CDN，验证请求没有正确到达源站。
- 域名状态异常。

## 十五、DNS 安全

### 1. DNS 劫持

DNS 劫持是指解析结果被恶意篡改，用户访问域名时被引导到错误地址。

防护方式：

- 使用可信 DNS 服务。
- 重要域名开启 DNSSEC。
- 网站使用 HTTPS。
- 用户侧避免使用不可信网络。

### 2. DNSSEC

DNSSEC 用数字签名验证 DNS 记录是否被篡改。

作用：

- 验证 DNS 数据完整性。
- 防止部分 DNS 欺骗攻击。

注意：

- DNSSEC 不能加密查询内容。
- 配置错误可能导致域名无法解析。
- 开启前要确认注册商和 DNS 服务商都支持。

### 3. CAA

CAA 可以限制哪些 CA 可以为域名签发证书。

好处：

- 降低证书被错误签发的风险。

风险：

- 配错会导致正常证书签发失败。

### 4. 域名账号安全

建议：

- 注册商账号开启多因素认证。
- 开启域名转移锁。
- 使用强密码。
- 限制 DNS 管理权限。
- 定期检查 DNS 记录。
- 删除不用的子域名记录。
- 防止子域名接管。

### 5. 子域名接管

如果 DNS 中存在 CNAME 指向某个第三方平台，但该平台上的资源已经删除，攻击者可能重新创建同名资源接管该子域名。

常见风险：

```text
old.example.com CNAME old-site.third-party.com
```

如果第三方平台上的 `old-site` 已被删除，就要及时删除这条 DNS 记录。

## 十六、域名接入网站的完整步骤

以把 `example.com` 绑定到一台服务器为例：

1. 购买域名。
2. 在注册商处确认域名状态正常。
3. 选择 DNS 服务商。
4. 在注册商处设置 nameserver，或使用注册商默认 DNS。
5. 在 DNS 面板添加 A 记录。
6. 服务器开放 80 和 443 端口。
7. Web 服务器配置域名。
8. 申请并配置 HTTPS 证书。
9. 使用 `dig` 或 `nslookup` 验证解析结果。
10. 使用浏览器和 `curl -I` 验证网站访问。
11. 配置监控和证书续期。

## 十七、学习重点

- 域名是给人看的名字，IP 是计算机通信使用的地址。
- DNS 负责把域名解析为 IP 或其他服务记录。
- 域名解析链路是：根 DNS -> TLD DNS -> 权威 DNS。
- 用户通常查询递归 DNS，递归 DNS 代替用户完成完整查询。
- A 记录指向 IPv4，AAAA 指向 IPv6，CNAME 指向另一个域名。
- MX 用于邮件，TXT 常用于验证和邮件安全。
- TTL 决定缓存时间，影响解析修改后的生效速度。
- DNS 不负责 HTTP 跳转，跳转要在 Web 服务器、CDN 或负载均衡配置。
- HTTPS 证书必须匹配访问的域名。
- 排查 DNS 问题时要区分权威 DNS 结果和递归 DNS 缓存结果。

## 十八、常用检查清单

域名无法访问时：

- 域名是否过期。
- nameserver 是否正确。
- 权威 DNS 是否有记录。
- A / CNAME 记录是否正确。
- TTL 是否还没过期。
- 本机 DNS 缓存是否需要清理。
- 服务器端口是否开放。
- Web 服务是否绑定该域名。
- HTTPS 证书是否匹配。
- CDN 或代理配置是否正确。

新增域名解析时：

- 主机记录是否写对。
- 记录类型是否选对。
- 记录值是否正确。
- 是否和已有记录冲突。
- TTL 是否符合切换需求。
- 是否需要同时配置 `@` 和 `www`。
- 是否需要配置 HTTPS 证书。
- 是否需要配置邮件相关记录。
