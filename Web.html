    计算机网络笔记

    一、计算机网络概述

    1. 什么是计算机网络

    计算机网络是指把分布在不同地理位置的计算机、服务器、终端设备和网络设备，通过通信线路连接起来，实现数据通信、资源共享和协同工作的系统。

    网络的核心目标：

    • 数据通信：让不同设备之间可以交换信息。
    • 资源共享：共享文件、打印机、服务器、数据库等资源。
    • 分布式处理：多台设备共同完成任务。
    • 提高可靠性：某些节点故障时，仍可通过其他路径通信。

    2. 网络的分类

    按覆盖范围划分：

    类型 中文名 特点 示例
    PAN 个人区域网 范围很小，围绕个人设备 蓝牙耳机、手机热点
    LAN 局域网 范围较小，速度快，延迟低 家庭网络、校园网、公司内网
    MAN 城域网 覆盖一个城市或地区 城市政务网络
    WAN 广域网 跨地区、跨国家 互联网

    按传输介质划分：

    • 有线网络：双绞线、同轴电缆、光纤。
    • 无线网络：Wi-Fi、蓝牙、蜂窝网络、卫星通信。

    按交换方式划分：

    • 电路交换：通信前先建立固定线路，典型例子是传统电话网络。
    • 分组交换：把数据拆成多个分组独立传输，互联网主要采用这种方式。
    • 报文交换：以完整报文为单位存储转发，现在较少直接使用。

    3. 常见网络拓扑

    • 总线型：所有设备共享一条通信线路，结构简单但冲突多。
    • 星型：设备连接到中心交换设备，现代局域网常用。
    • 环型：设备首尾相连形成环，数据沿固定方向传输。
    • 网状型：节点之间有多条连接，可靠性高，成本也高。
    • 树型：分层结构，适合大型网络管理。

    二、网络体系结构

    1. OSI 七层模型

    层次 名称 作用 常见协议或设备
    7 应用层 为用户应用提供网络服务 HTTP、DNS、FTP、SMTP
    6 表示层 数据格式转换、加密、压缩 SSL/TLS、JPEG、ASCII
    5 会话层 建立、管理和释放会话 RPC、NetBIOS
    4 传输层 端到端传输、可靠性控制 TCP、UDP
    3 网络层 IP 寻址和路由选择 IP、ICMP、路由器
    2 数据链路层 帧传输、MAC 地址、差错检测 Ethernet、交换机
    1 物理层 比特流传输 网线、光纤、集线器

    2. TCP/IP 四层模型

    TCP/IP 模型 对应 OSI 层 主要功能
    应用层 应用层、表示层、会话层 具体应用协议
    传输层 传输层 进程到进程通信
    网际层 网络层 IP 寻址和路由
    网络接口层 数据链路层、物理层 局域网传输和物理传输

    3. 数据封装过程

    发送数据时，数据会从高层向低层逐层封装：

    应用数据
  -> 传输层加 TCP/UDP 首部，形成段 Segment
  -> 网络层加 IP 首部，形成包 Packet
  -> 数据链路层加帧头帧尾，形成帧 Frame
  -> 物理层转换为比特流 Bit

    接收数据时，过程相反，逐层解封装。

    三、物理层

    物理层负责在传输介质上传输原始比特流。

    1. 常见传输介质

    • 双绞线：局域网常用，成本低，常见接口是 RJ-45。
    • 光纤：传输距离远，速度快，抗干扰能力强。
    • 无线电波：用于 Wi-Fi、蓝牙、蜂窝网络。

    2. 常见单位

    • bit：比特，网络传输的基本单位。
    • Byte：字节，1 Byte = 8 bit。
    • Mbps：每秒百万比特。
    • MB/s：每秒百万字节。

    换算示例：

    100 Mbps ≈ 12.5 MB/s

    实际下载速度还要扣除协议开销，所以通常达不到理论值。

    四、数据链路层

    数据链路层负责在同一链路或同一局域网内传输数据帧。

    1. MAC 地址

    MAC 地址是网卡的硬件地址，长度为 48 位，通常写成：

    00-1A-2B-3C-4D-5E

    特点：

    • 用于局域网内部识别设备。
    • 交换机根据 MAC 地址转发数据帧。
    • MAC 地址工作在数据链路层。

    2. 以太网帧

    以太网帧的核心字段：

    • 目标 MAC 地址
    • 源 MAC 地址
    • 类型字段
    • 数据部分
    • FCS 校验字段

    FCS 通常使用 CRC 校验，用于发现传输错误。

    3. 交换机工作原理

    交换机主要根据 MAC 地址表转发数据：

    1. 收到数据帧后，记录源 MAC 地址和对应端口。
    2. 查找目标 MAC 地址所在端口。
    3. 如果找到目标端口，就只向该端口转发。
    4. 如果找不到目标端口，就向除接收端口外的其他端口广播。

    交换机比集线器更高效，因为它不会无脑广播所有数据。

    4. 广播与冲突

    • 冲突域：同一时间只能有一个设备发送数据的范围。
    • 广播域：广播帧可以到达的范围。
    • 交换机可以隔离冲突域。
    • 路由器可以隔离广播域。

    5. VLAN

    VLAN 是虚拟局域网，可以在同一物理交换机上划分多个逻辑网络。

    作用：

    • 隔离广播域。
    • 提高安全性。
    • 方便网络管理。

    五、网络层

    网络层负责跨网络传输数据包，核心任务是 IP 寻址和路由选择。

    1. IP 地址

    IPv4 地址长度为 32 位，通常写成点分十进制：

    192.168.1.10

    IP 地址由两部分组成：

    • 网络号：标识所属网络。
    • 主机号：标识该网络中的具体主机。

    IP 协议的特点：

    • 无连接：发送 IP 数据包前，不需要先建立连接。
    • 尽力而为：IP 只尽力转发，不保证一定送达。
    • 不保证顺序：多个数据包可能经过不同路径，到达顺序可能不同。
    • 不负责重传：丢包后的重传通常由 TCP 或应用层处理。

    IPv4 报文头中的重要字段：

    字段 作用
    Version IP 协议版本，IPv4 中值为 4
    Header Length IP 首部长度
    Total Length 整个 IP 数据包长度
    Identification 分片重组时识别同一个数据包
    Flags 控制是否允许分片，如 DF、MF
    Fragment Offset 分片偏移量
    TTL 生存时间，每经过一个路由器减 1
    Protocol 上层协议，如 TCP 为 6，UDP 为 17，ICMP 为 1
    Header Checksum IP 首部校验和
    Source IP 源 IP 地址
    Destination IP 目标 IP 地址

    TTL 的作用是防止数据包在网络中无限循环。路由器每转发一次，TTL 减 1；当 TTL 变为 0 时，路由器丢弃该包，并可能返回 ICMP 超时报文。

    常见特殊 IPv4 地址：

    地址 含义
    0.0.0.0 未指定地址，也可表示监听本机所有网卡
    127.0.0.1 本机回环地址，常用于测试本机服务
    169.254.0.0/16 自动私有地址，通常表示 DHCP 获取地址失败
    255.255.255.255 受限广播地址，只在本地网络内广播
    网络地址 主机位全为 0，表示整个网段
    广播地址 主机位全为 1，表示该网段内所有主机

    IPv6 地址长度为 128 位，通常使用十六进制和冒号表示：

    2001:0db8:0000:0000:0000:ff00:0042:8329

    IPv6 可以压缩连续的 0：

    2001:db8::ff00:42:8329

    IPv6 的特点：

    • 地址空间极大，缓解 IPv4 地址不足。
    • 不使用广播，改用多播和任播。
    • 首部结构比 IPv4 更简化。
    • 支持自动地址配置。
    • 常见回环地址是 ::1。
    • 常见链路本地地址前缀是 fe80::/10。

    2. 子网掩码

    子网掩码用于区分 IP 地址中的网络号和主机号。

    示例：

    IP 地址：     192.168.1.10
子网掩码：   255.255.255.0
网络地址：   192.168.1.0
广播地址：   192.168.1.255
可用主机：   192.168.1.1 ~ 192.168.1.254

    判断两个 IP 是否在同一网段，需要把 IP 地址和子网掩码进行按位与运算。如果得到的网络地址相同，说明它们在同一网段。

    示例：

    192.168.1.10  AND  255.255.255.0  = 192.168.1.0
192.168.1.20  AND  255.255.255.0  = 192.168.1.0

    这两个地址的网络地址相同，所以属于同一网段。

    3. CIDR 表示法

    CIDR 用斜杠表示网络前缀长度：

    192.168.1.0/24

    /24 表示前 24 位是网络号。

    常见前缀：

    CIDR 子网掩码 可用主机数
    /24 255.255.255.0 254
    /25 255.255.255.128 126
    /26 255.255.255.192 62
    /27 255.255.255.224 30
    /30 255.255.255.252 2

    可用主机数计算：

    可用主机数 = 2^(主机位数) - 2

    减去的 2 个地址分别是网络地址和广播地址。

    子网划分示例：

    原网络：192.168.10.0/24
需求：划分为 4 个子网

    需要借 2 位主机位作为子网位，因为 2^2 = 4。新的前缀长度为 /26。

    子网 网络地址 可用主机范围 广播地址
    1 192.168.10.0/26 192.168.10.1 ~ 192.168.10.62 192.168.10.63
    2 192.168.10.64/26 192.168.10.65 ~ 192.168.10.126 192.168.10.127
    3 192.168.10.128/26 192.168.10.129 ~ 192.168.10.190 192.168.10.191
    4 192.168.10.192/26 192.168.10.193 ~ 192.168.10.254 192.168.10.255

    子网划分的关键步骤：

    1. 明确需要多少个子网或每个子网需要多少主机。
    2. 根据需求确定需要借几位。
    3. 计算新的子网掩码。
    4. 计算每个子网的网络地址、广播地址和可用地址范围。

    4. 私有 IP 地址

    私有地址只能在内网使用，不能直接在公网路由。

    地址范围 CIDR
    10.0.0.0 ~ 10.255.255.255 10.0.0.0/8
    172.16.0.0 ~ 172.31.255.255 172.16.0.0/12
    192.168.0.0 ~ 192.168.255.255 192.168.0.0/16

    5. 默认网关

    默认网关是主机访问其他网络时交给的下一跳设备，通常是路由器接口地址。

    如果目标 IP 和本机不在同一网段，数据会先发给默认网关。

    主机发送数据时的判断流程：

    1. 主机先用自己的 IP 和子网掩码算出本机网络地址。
    2. 再用目标 IP 和子网掩码算出目标网络地址。
    3. 如果两个网络地址相同，说明目标在同一局域网，直接通过 ARP 查目标 MAC。
    4. 如果两个网络地址不同，说明目标在其他网络，先通过 ARP 查默认网关的 MAC。
    5. 数据帧的目标 MAC 是下一跳设备的 MAC，但 IP 包里的目标 IP 仍然是最终目标 IP。

    也就是说，跨网段通信时，MAC 地址每经过一跳都会改变，IP 地址通常保持不变，除非经过 NAT。

    6. ARP 协议

    ARP 用于根据 IP 地址查询对应的 MAC 地址。

    工作过程：

    1. 主机想发送数据给同一局域网内的某个 IP。
    2. 如果不知道目标 MAC，就发送 ARP 广播。
    3. 目标主机收到后回复自己的 MAC 地址。
    4. 发送方把 IP 与 MAC 的映射保存到 ARP 缓存中。

    注意：

    • ARP 只在局域网内工作。
    • ARP 欺骗是常见内网攻击方式。

    ARP 缓存可以减少重复广播。Windows 可用 arp -a 查看 ARP 缓存。

    常见 ARP 类型：

    • 普通 ARP：根据目标 IP 查询目标 MAC。
    • 免费 ARP：主机主动广播自己的 IP 和 MAC，用于检测地址冲突或更新其他设备缓存。
    • 代理 ARP：路由器代替其他主机回应 ARP 请求，常见于特殊网络场景。

    7. ICMP 协议

    ICMP 用于网络控制和错误报告。

    常见用途：

    • ping：测试主机是否可达。
    • tracert 或 traceroute：追踪数据包经过的路由。

    ping 通常使用 ICMP Echo Request 和 Echo Reply。目标不响应 ping 不一定表示目标不可达，也可能是防火墙禁用了 ICMP。

    tracert 的核心思路是逐步增加 TTL：

    1. 第一个包 TTL 为 1，到第一跳路由器后 TTL 变为 0，被丢弃。
    2. 第一跳路由器返回 ICMP 超时消息。
    3. 第二个包 TTL 为 2，可以到第二跳。
    4. 不断重复，直到到达目标主机。

    8. NAT

    NAT 是网络地址转换，常用于家庭或企业网络中。

    作用：

    • 让多个内网设备共享一个公网 IP 上网。
    • 隐藏内部网络结构。
    • 缓解 IPv4 地址不足。

    常见类型：

    • 静态 NAT：一个内网地址固定映射一个公网地址。
    • 动态 NAT：从公网地址池中动态分配。
    • PAT：多个内网地址通过不同端口复用同一个公网地址，家庭路由器常用。

    9. 路由

    路由是为数据包选择转发路径的过程。

    路由表常见字段：

    • 目标网络
    • 子网掩码或前缀长度
    • 下一跳地址
    • 出接口
    • 度量值

    常见路由类型：

    • 直连路由：设备接口直接连接的网络。
    • 静态路由：管理员手动配置。
    • 动态路由：路由器通过协议自动学习，如 RIP、OSPF、BGP。

    六、传输层

    传输层负责进程到进程之间的通信。网络层只负责主机到主机，传输层通过端口号定位具体应用进程。

    1. 端口号

    端口号范围：0 ~ 65535。

    常见端口：

    端口 协议 作用
    20/21 FTP 文件传输
    22 SSH 远程登录
    25 SMTP 邮件发送
    53 DNS 域名解析
    80 HTTP Web 服务
    110 POP3 邮件接收
    143 IMAP 邮件接收
    443 HTTPS 加密 Web 服务
    3306 MySQL 数据库
    6379 Redis 缓存数据库

    2. UDP

    UDP 是无连接、不可靠、面向报文的传输协议。

    特点：

    • 不建立连接。
    • 不保证可靠到达。
    • 没有复杂的重传和拥塞控制。
    • 首部开销小，速度快。

    适用场景：

    • DNS 查询
    • 视频直播
    • 在线语音
    • 游戏实时通信

    3. TCP

    TCP 是面向连接、可靠、面向字节流的传输协议。

    特点：

    • 建立连接后再传输数据。
    • 保证数据可靠、有序到达。
    • 支持确认、重传、流量控制、拥塞控制。
    • 开销比 UDP 大。

    适用场景：

    • 网页浏览
    • 文件传输
    • 邮件传输
    • 数据库连接

    4. TCP 三次握手

    三次握手用于建立连接：

    客户端 -> 服务端：SYN
服务端 -> 客户端：SYN + ACK
客户端 -> 服务端：ACK

    三次握手的目的：

    • 确认双方发送和接收能力正常。
    • 同步初始序列号。
    • 建立可靠连接的状态。

    5. TCP 四次挥手

    四次挥手用于释放连接：

    主动关闭方 -> 被动关闭方：FIN
被动关闭方 -> 主动关闭方：ACK
被动关闭方 -> 主动关闭方：FIN
主动关闭方 -> 被动关闭方：ACK

    为什么通常是四次：

    TCP 是全双工通信，双方的发送通道需要分别关闭。一方说“我发完了”，另一方可能还有数据要发送，所以 FIN 和 ACK 往往分开发送。

    6. TCP 可靠传输机制

    TCP 可靠性主要依靠：

    • 序列号：给字节流编号，保证顺序。
    • 确认应答：接收方收到数据后返回 ACK。
    • 超时重传：发送后长时间未收到 ACK 就重传。
    • 快速重传：收到多个重复 ACK 时提前重传。
    • 校验和：检测数据是否出错。

    7. 流量控制

    流量控制用于避免发送方发送太快，导致接收方缓冲区溢出。

    TCP 使用滑动窗口机制：

    • 接收方通过窗口大小告诉发送方自己还能接收多少数据。
    • 发送方根据窗口大小控制发送速率。

    8. 拥塞控制

    拥塞控制用于避免网络中数据过多导致严重丢包和延迟。

    常见算法阶段：

    • 慢启动：拥塞窗口从小开始指数增长。
    • 拥塞避免：窗口增长变慢，线性增长。
    • 快速重传：发现丢包后尽快重传。
    • 快速恢复：降低窗口后继续传输。

    七、应用层协议

    1. DNS

    DNS 用于把域名解析为 IP 地址。

    DNS 的全称是 Domain Name System，中文常称为域名系统。人更容易记住域名，例如 www.example.com；计算机通信最终需要 IP 地址，所以访问网站前通常要先做 DNS 解析。

    DNS 的核心作用：

    • 域名解析：把域名转换为 IP 地址。
    • 服务发现：通过 MX、SRV 等记录找到对应服务。
    • 负载均衡：同一个域名可以返回多个 IP。
    • 容灾切换：通过调整解析结果，把流量切到其他服务器。

    DNS 层级结构

    DNS 是分层的树状结构：

    根域 .
  -> 顶级域 .com / .cn / .org
    -> 二级域 example.com
      -> 主机名 www.example.com

    常见 DNS 服务器类型：

    类型 作用
    根域名服务器 告诉查询者顶级域名服务器在哪里
    顶级域名服务器 管理 .com、.cn 等顶级域
    权威域名服务器 保存某个域名的真实 DNS 记录
    本地递归 DNS 服务器 代替客户端完成完整查询，常由运营商、公司或公共 DNS 提供

    DNS 解析过程

    以解析 www.example.com 为例：

    1. 浏览器检查自身缓存。
    2. 操作系统检查 DNS 缓存。
    3. 检查本地 hosts 文件。
    4. 如果本地没有结果，就查询本地递归 DNS 服务器。
    5. 本地递归 DNS 服务器向根域名服务器查询 .com 的服务器地址。
    6. 再向 .com 顶级域名服务器查询 example.com 的权威服务器地址。
    7. 再向 example.com 的权威域名服务器查询 www.example.com 的记录。
    8. 权威服务器返回 IP 地址。
    9. 本地递归 DNS 缓存结果，并返回给客户端。
    10. 浏览器拿到 IP 后再建立 TCP 或 QUIC 连接。

    递归查询和迭代查询

    • 递归查询：客户端把问题交给本地 DNS，本地 DNS 负责查到底，并返回最终结果。
    • 迭代查询：DNS 服务器不直接给最终答案，而是告诉查询者下一步应该问谁。

    普通用户设备一般向本地 DNS 发起递归查询；本地 DNS 再向根、顶级域、权威 DNS 发起迭代查询。

    DNS 缓存和 TTL

    DNS 结果通常会被缓存，缓存位置包括：

    • 浏览器缓存
    • 操作系统缓存
    • 本地递归 DNS 缓存
    • 路由器或网关缓存
    • 应用程序自己的缓存

    TTL 表示 DNS 记录可以缓存多久，单位是秒。

    例如：

    www.example.com.  300  IN  A  93.184.216.34

    这里 300 表示该记录可以缓存 300 秒。

    TTL 的影响：

    • TTL 较大：缓存时间长，解析压力小，但变更生效慢。
    • TTL 较小：变更生效快，但 DNS 查询次数更多。

    常见 DNS 记录：

    记录类型 作用
    A 域名到 IPv4 地址
    AAAA 域名到 IPv6 地址
    CNAME 域名别名
    MX 邮件服务器
    NS 域名服务器
    TXT 文本记录，常用于验证
    SOA 权威区域的起始授权记录
    PTR 反向解析，把 IP 解析为域名
    SRV 指定某个服务的位置和端口
    CAA 指定哪些 CA 可以为域名签发证书

    记录示例：

    example.com.        A      93.184.216.34
www.example.com.    CNAME  example.com.
example.com.        MX     10 mail.example.com.

    注意点：

    • A 和 AAAA 返回的是 IP 地址。
    • CNAME 返回的是另一个域名，客户端还需要继续解析。
    • 一个域名可以有多个 A 记录，用于简单负载均衡。
    • 邮件服务通常依赖 MX 记录。
    • 反向 DNS 使用 PTR 记录。

    DNS 使用的传输协议

    DNS 默认使用 UDP 53 端口，因为 UDP 开销小、速度快。

    在以下场景中可能使用 TCP 53 端口：

    • 响应数据太大，UDP 放不下。
    • 进行区域传送。
    • 客户端或服务器要求使用 TCP。

    现代场景还可能使用：

    • DoT：DNS over TLS，通常使用 853 端口。
    • DoH：DNS over HTTPS，使用 HTTPS 加密 DNS 查询。

    常见 DNS 问题

    问题 可能原因
    能 ping IP，不能访问域名 DNS 配置错误或 DNS 服务异常
    域名解析到旧 IP DNS 缓存未过期
    NXDOMAIN 域名不存在
    SERVFAIL DNS 服务器查询失败
    解析结果不稳定 负载均衡、CDN 或不同地区线路导致

    常用排查命令：

    nslookup www.example.com
ipconfig /flushdns

    dig www.example.com
dig www.example.com A
dig www.example.com CNAME
dig +trace www.example.com

    2. HTTP

    HTTP 是超文本传输协议，主要用于浏览器和服务器之间通信。

    特点：

    • 基于请求-响应模型。
    • 默认使用 TCP。
    • HTTP 本身是无状态协议。
    • 明文传输，内容可能被窃听或篡改。
    • 灵活，可传输 HTML、JSON、图片、视频等多种资源。

    URL 结构

    URL 用于定位网络资源。

    https://www.example.com:443/path/index.html?keyword=network&page=1#title

    组成部分：

    部分 示例 含义
    协议 https 使用的应用层协议
    主机名 www.example.com 服务器域名
    端口 443 服务监听端口
    路径 /path/index.html 资源在服务器上的位置
    查询字符串 keyword=network&page=1 传递给服务器的参数
    片段标识 #title 页面内部定位，不会发送给服务器

    HTTP 请求报文

    HTTP 请求由请求行、请求头、空行和请求体组成。

    GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: text/html

    请求行包含：

    • 请求方法：如 GET、POST。
    • 请求路径：如 /index.html。
    • HTTP 版本：如 HTTP/1.1。

    如果是提交 JSON 数据，请求可能是：

    POST /api/users HTTP/1.1
Host: www.example.com
Content-Type: application/json
Content-Length: 37

{"name":"Alice","age":18}

    HTTP 响应报文

    HTTP 响应由状态行、响应头、空行和响应体组成。

    HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 1256
Cache-Control: max-age=3600

<html>...</html>

    状态行包含：

    • HTTP 版本
    • 状态码
    • 原因短语

    常见请求方法：

    方法 作用
    GET 获取资源
    POST 提交数据或创建资源
    PUT 整体更新资源
    PATCH 部分更新资源
    DELETE 删除资源
    HEAD 只获取响应头
    OPTIONS 查询服务器支持的方法

    方法特性：

    方法 是否安全 是否幂等 说明
    GET 是 是 只获取资源，不应修改服务器状态
    HEAD 是 是 类似 GET，但只返回响应头
    POST 否 否 常用于提交表单、创建订单
    PUT 否 是 多次整体替换同一资源，结果应一致
    PATCH 否 不一定 部分更新资源
    DELETE 否 是 多次删除同一资源，结果通常一致

    安全方法指语义上不应修改服务器状态；幂等指同一个请求执行一次和执行多次，对资源状态的影响应该相同。

    常见状态码：

    状态码 含义
    200 请求成功
    201 创建成功
    301 永久重定向
    302 临时重定向
    304 使用缓存
    400 请求错误
    401 未认证
    403 无权限
    404 资源不存在
    500 服务器内部错误
    502 网关错误
    503 服务不可用

    状态码分类：

    范围 类型 含义
    1xx 信息响应 请求已收到，继续处理
    2xx 成功 请求成功处理
    3xx 重定向 需要进一步操作
    4xx 客户端错误 请求有问题
    5xx 服务端错误 服务器处理失败

    更多常见状态码：

    状态码 含义 常见场景
    204 无响应体 删除成功但不返回内容
    206 部分内容 分片下载、视频拖动
    307 临时重定向 保持原请求方法重定向
    308 永久重定向 保持原请求方法永久重定向
    405 方法不允许 用 POST 访问只支持 GET 的接口
    408 请求超时 客户端发送请求太慢
    409 冲突 资源状态冲突
    413 请求体太大 上传文件超过限制
    429 请求过多 被限流
    504 网关超时 代理服务器等不到上游响应

    常见请求头

    请求头 作用
    Host 指定访问的主机名，HTTP/1.1 必需
    User-Agent 客户端信息，如浏览器和系统
    Accept 客户端希望接收的数据类型
    Accept-Encoding 客户端支持的压缩方式，如 gzip、br
    Content-Type 请求体的数据类型
    Content-Length 请求体长度
    Authorization 身份认证信息
    Cookie 携带浏览器保存的 Cookie
    Referer 请求来源页面
    Origin 跨域请求来源
    Cache-Control 控制缓存策略

    常见响应头

    响应头 作用
    Content-Type 响应体的数据类型
    Content-Length 响应体长度
    Content-Encoding 响应体压缩方式
    Set-Cookie 让浏览器保存 Cookie
    Location 重定向目标地址
    Cache-Control 缓存控制
    ETag 资源版本标识
    Last-Modified 资源最后修改时间
    Access-Control-Allow-Origin CORS 跨域访问控制
    Server 服务器软件信息

    HTTP 无状态与 Cookie

    HTTP 本身无状态，服务器默认不知道两次请求是否来自同一个用户。

    为了解决登录状态问题，常用 Cookie、Session 或 Token：

    • Cookie：浏览器保存的小段数据，请求同一站点时自动携带。
    • Session：服务端保存会话数据，客户端通常只保存 Session ID。
    • Token：客户端保存令牌，请求时放入 Authorization 请求头或 Cookie。

    Cookie 重要属性：

    属性 作用
    Expires / Max-Age 设置过期时间
    Domain 指定 Cookie 生效域名
    Path 指定 Cookie 生效路径
    HttpOnly 禁止 JavaScript 读取，降低 XSS 风险
    Secure 只在 HTTPS 下发送
    SameSite 限制跨站请求携带 Cookie，降低 CSRF 风险

    HTTP 缓存

    HTTP 缓存可以减少重复下载，提高访问速度。

    强缓存：浏览器直接使用本地缓存，不向服务器确认。

    常见响应头：

    Cache-Control: max-age=3600

    含义是资源 3600 秒内可直接使用缓存。

    常见 Cache-Control 指令：

    指令 含义
    max-age=秒数 缓存有效时间
    no-cache 使用缓存前必须向服务器验证
    no-store 不允许保存缓存
    public 可被浏览器和代理服务器缓存
    private 只能被用户浏览器缓存

    协商缓存：浏览器询问服务器资源是否变化，没变化就返回 304 Not Modified。

    常见机制：

    ETag: "abc123"
If-None-Match: "abc123"

    Last-Modified: Tue, 19 May 2026 10:00:00 GMT
If-Modified-Since: Tue, 19 May 2026 10:00:00 GMT

    如果资源未变化，服务器返回：

    HTTP/1.1 304 Not Modified

    HTTP 连接管理

    HTTP/1.0 默认短连接，一个请求通常对应一次 TCP 连接。

    HTTP/1.1 默认支持长连接：

    Connection: keep-alive

    长连接可以复用 TCP 连接，减少三次握手和慢启动开销。

    HTTP/1.1 仍存在队头阻塞问题：同一连接上的请求需要按顺序处理，前面的响应慢，会影响后面的响应。

    HTTP/2 的改进：

    • 二进制分帧。
    • 多路复用，同一连接上并发多个请求和响应。
    • 头部压缩。
    • 支持流优先级。

    HTTP/3 的改进：

    • 基于 QUIC，而不是直接基于 TCP。
    • QUIC 基于 UDP。
    • 减少连接建立延迟。
    • 缓解 TCP 层面的队头阻塞。

    跨域 CORS

    浏览器有同源策略。协议、域名、端口三者都相同，才算同源。

    例如：

    https://example.com:443

    和下面地址不是同源：

    http://example.com:80
https://api.example.com:443
https://example.com:8443

    CORS 通过 HTTP 头允许跨域访问。

    常见响应头：

    Access-Control-Allow-Origin: https://www.example.com
Access-Control-Allow-Methods: GET, POST, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization

    复杂跨域请求前，浏览器会先发送 OPTIONS 预检请求。

    3. HTTPS

    HTTPS = HTTP + TLS。

    HTTPS 的作用：

    • 加密传输内容，防止窃听。
    • 校验数据完整性，防止篡改。
    • 通过证书验证服务器身份，防止伪造网站。

    HTTP 明文传输，任何能截获流量的中间节点都可能看到请求内容。HTTPS 在 HTTP 与 TCP 之间加入 TLS，加密 HTTP 报文。

TLS

    TLS 的安全目标

    目标 说明
    身份认证 确认访问的服务器确实是目标网站
    机密性 传输内容被加密，中间人难以读取
    完整性 数据被篡改时能够被发现

    对称加密和非对称加密

    HTTPS 同时使用对称加密和非对称加密：

    • 非对称加密：用于身份认证和密钥协商，计算成本较高。
    • 对称加密：用于大量应用数据传输，速度快。

    简化理解：

    1. 握手阶段用证书和非对称密码学确认身份、协商密钥。
    2. 数据传输阶段使用协商出的对称密钥加密 HTTP 内容。

    数字证书

    服务器证书通常包含：

    • 域名
    • 公钥
    • 证书有效期
    • 证书颁发机构 CA
    • CA 的数字签名

    浏览器验证证书时会检查：

    • 证书是否过期。
    • 证书域名是否匹配当前访问域名。
    • 证书是否由受信任 CA 签发。
    • 证书链是否完整。
    • 证书是否被吊销。

    TLS 握手简化过程

    1. 客户端请求建立 HTTPS 连接。
    2. 客户端发送支持的 TLS 版本、加密套件和随机数。
    3. 服务端选择 TLS 版本和加密套件，返回证书和随机数。
    4. 客户端验证证书是否合法。
    5. 双方通过密钥协商算法生成会话密钥。
    6. 后续 HTTP 数据使用会话密钥加密传输。

    SNI

    SNI 是 Server Name Indication。它允许客户端在 TLS 握手时告诉服务器自己要访问哪个域名。

    没有 SNI 时，同一个 IP 上部署多个 HTTPS 站点会比较困难，因为服务器不知道应该返回哪张证书。

    HSTS

    HSTS 是 HTTP Strict Transport Security，用于强制浏览器使用 HTTPS 访问网站。

    响应头示例：

    Strict-Transport-Security: max-age=31536000; includeSubDomains

    启用 HSTS 后，浏览器会在有效期内自动把 HTTP 请求升级为 HTTPS。

    HTTPS 常见问题

    问题 可能原因
    证书不受信任 使用自签名证书或 CA 不受浏览器信任
    证书过期 证书超过有效期
    域名不匹配 证书绑定的域名不是当前访问域名
    证书链不完整 服务器没有正确配置中间证书
    混合内容 HTTPS 页面中加载了 HTTP 资源

    4. DHCP

    DHCP 用于自动分配网络配置。

    常见分配内容：

    • IP 地址
    • 子网掩码
    • 默认网关
    • DNS 服务器地址

    DHCP 获取地址的过程：

    Discover -> Offer -> Request -> ACK

    5. FTP、SMTP、POP3、IMAP

    • FTP：文件传输协议。
    • SMTP：发送邮件。
    • POP3：下载邮件到本地。
    • IMAP：在服务器上同步管理邮件。

    八、浏览器访问网页的完整过程

    以访问 https://www.example.com 为例：

    1. 浏览器解析 URL，判断协议、域名、端口和路径。
    2. 查询浏览器缓存，检查是否已有可用资源。
    3. 进行 DNS 解析，获得服务器 IP 地址。
    4. 通过 ARP 获取网关或目标主机的 MAC 地址。
    5. 建立 TCP 连接，完成三次握手。
    6. 如果是 HTTPS，进行 TLS 握手并协商密钥。
    7. 浏览器发送 HTTP 请求。
    8. 服务器处理请求并返回 HTTP 响应。
    9. 浏览器解析 HTML，继续请求 CSS、JavaScript、图片等资源。
    10. 浏览器构建 DOM、CSSOM，生成渲染树并绘制页面。
    11. 连接可能保持复用，也可能在空闲后关闭。

    九、网络安全基础

    1. 安全三要素

    • 机密性：数据不能被未授权者读取。
    • 完整性：数据不能被非法篡改。
    • 可用性：系统和服务需要在需要时可用。

    2. 常见攻击

    攻击方式 说明
    DDoS 利用大量流量压垮目标服务
    ARP 欺骗 伪造 IP 与 MAC 的对应关系
    DNS 劫持 篡改域名解析结果
    中间人攻击 攻击者插入通信双方之间窃听或篡改数据
    钓鱼攻击 伪造网站或消息骗取账号密码
    端口扫描 探测目标主机开放的服务

    3. 常见防护手段

    • 使用 HTTPS、SSH 等加密协议。
    • 配置防火墙和访问控制策略。
    • 及时更新系统和软件补丁。
    • 使用强密码和多因素认证。
    • 对重要服务限制来源 IP。
    • 定期查看日志，发现异常访问。
    • 在公共网络中谨慎使用未加密服务。

    4. 防火墙

    防火墙根据规则允许或拒绝网络流量。

    常见过滤依据：

    • 源 IP
    • 目标 IP
    • 源端口
    • 目标端口
    • 协议类型
    • 连接状态

    十一、常见故障排查思路

    1. 无法上网

    排查顺序：

    1. 检查网线、Wi-Fi、网卡是否正常。
    2. 查看是否获取到正确的 IP 地址。
    3. 检查默认网关是否正确。
    4. ping 127.0.0.1，测试本机 TCP/IP 协议栈。
    5. ping 本机 IP，测试网卡配置。
    6. ping 网关 IP，测试局域网连通性。
    7. ping 公网 IP，测试是否能访问外网。
    8. nslookup 域名，检查 DNS 是否正常。

    2. 能 ping IP，但不能访问域名

    通常是 DNS 问题。

    可能原因：

    • DNS 服务器配置错误。
    • DNS 缓存异常。
    • 本地 hosts 文件配置错误。
    • DNS 被劫持或污染。

    3. 能访问网站，但速度慢

    可能原因：

    • 本地带宽不足。
    • Wi-Fi 信号弱。
    • 线路拥塞。
    • DNS 解析慢。
    • 服务器响应慢。
    • 丢包率高。

    4. 某个端口无法访问

    排查方向：

    • 服务是否启动。
    • 服务是否监听正确端口。
    • 防火墙是否放行。
    • 路由是否可达。
    • NAT 或端口映射是否正确。
    • 云服务器安全组是否开放。
